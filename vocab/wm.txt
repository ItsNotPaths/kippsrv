# Kinds a window manager adapter may emit. A new one is a deliberate edit
# here, not a thing that appears because one adapter drifted from another.
#
# A subject identifies the fact. A value goes in an attribute. Putting the
# title text in the subject would make every title a separate fact, and the
# store would keep all of them forever.
#
# Use an identifier, never a display name. A UUID, a MAC, a bus name or a
# connector never holds '=', and a name a person typed can. A '=' in a subject
# reads as the first attribute, so the fact loses its subject and collides
# with every other fact of its kind.
#
# The subject is the monitor, because a bar draws per monitor. A window
# manager that identifies things by window instead resolves that in its own
# adapter, which is the work an adapter exists to do.
focus       # <monitor>                       the focused monitor

# One fact for every tag of a monitor, not one for each tag. A per-tag fact can
# only say "this one is no longer selected" by leaving it out, and the store
# passes on a line that changed, never an absence. Moving between two empty
# tags reached no consumer at all until this replaced it.
tags        # <monitor> used=1,3 sel=2 urgent=

# The older shape, still what lua/wm/{sway,dwl,hypr,i3}.lua produce. They have
# the same hole and want the same treatment before anything reads them.
tag         # <monitor> <n> state=...         one line per non-empty tag
layout      # <monitor> <name>
title       # <monitor> text=              what to show for that monitor
app         # <monitor> id=                the focused application
mode        # <name>
win_open    # <id> mon= tag= appid=           event
win_close   # <id>                            event

# Commands a window manager adapter takes. Uppercase, per SPEC.md. These are
# convention: vocab.sh checks the kinds an adapter emits, not the verbs it
# claims. lint-core still forbids the core naming any of them.
#
# A bar that drives one window manager should drive the next one, which is the
# whole reason the list is here and not in each adapter's head.
VIEW        # <tag>      show that tag
TAG         # <tag>      move the focused window to it
TOGGLEVIEW  # <tag>
TOGGLETAG   # <tag>
LAYOUT      # <name>
FOCUS       # <n>        n places along the stack
MONITOR     # <n>
MOVE        # <n>        the focused window, to the next monitor
MASTER      # <delta>    the master area, as a fraction
NMASTER     # <n>
CLOSE
ZOOM
FLOAT
FULLSCREEN
RELOAD
QUIT
